Enygma is a confidential payments protocol: six banks transact on a public chain, but amounts, senders, and receivers stay hidden behind Pedersen commitments and a Groth16 zero-knowledge proof. This console walks through the full protocol, in order:

  1. I Setup — deploy-check the chain, initialize the Enygma contract, register its ZK verifier.
  2. II Bank Onboarding — register all 6 banks on-chain, then open each bank's own dashboard to run ML-KEM-768 Key Agreement (post-quantum, pairwise, off this screen).
  3. III Mint Supply — credit a bank's encrypted balance with tokens, as the operator.
  4. IV Balances & Verify — send a payment from a bank's own dashboard, then use the tools here to independently check the math behind what settled on-chain.

Random Factor · TxRandomValues
Each transfer produces 6 blinding factors. The sender's txRandom[0] = Σ raw_r[1..5]; each receiver's txRandom[i] = P − raw_r[i], so Σ txRandom ≡ 0 (mod P). Use these directly with Com(v, r) to verify on-chain balances.
Run a transfer first, then click Load Last Transfer.
Cumulative R · Balance Verification
Running sum of txRandom across all transfers. Pedersen commitments are additive: Σ Com(v, r) = Com(Σv, Σr) — so Com(cumulative_balance, cumulative_r) must match the on-chain commitment point.
Run at least one transfer, then click Refresh.
